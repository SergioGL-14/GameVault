# Playnite Steam Import and Metadata Model

Research checked on 2026-09-06 against official Playnite documentation and first-party source repositories. Source snapshots are Playnite core [`98c09dd`](https://github.com/JosefNemec/Playnite/commit/98c09dd6a16369feaa34c9661bc20b47566d76b1), PlayniteExtensions [`3085ebd`](https://github.com/JosefNemec/PlayniteExtensions/commit/3085ebd8b5906b53d3f005ef08141d641f4c469d), Playnite Backend [`12a6864`](https://codeberg.org/Playnite/Backend/commit/12a6864210e749558dbdc5737e0c6e15f582a0df), and Playnite Docs [`aa07876`](https://codeberg.org/Playnite/Docs/commit/aa07876a6646fe163cd9df5434918a893fa8119c).

## Conclusions

1. **Library discovery and metadata enrichment are separate stages.** `SteamLibrary.GetGames` delegates discovery to `SteamServiceAggregator.GetGamesAsync`. Playnite core imports each returned `GameMetadata`, deduplicating by the pair of library plugin ID and `GameId`; it then sends only newly added games to the metadata downloader. Existing games receive install-state and configured playtime updates, not another automatic metadata fill. [Steam entry point](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/SteamLibrary.cs#L76-L79), [Steam discovery](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/SteamLibrary.cs#L111-L115), [`GameDatabase.ImportGames`](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/Database/GameDatabase.cs#L1205-L1281), [`MainViewModelBase.UpdateLibraryData`](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/ViewModels/MainViewModelBase.cs#L741-L785)
2. **The Steam plugin initially returns identity and operational library data, not a complete catalog record.** Its default settings import locally installed games, do not connect an account, and do not import uninstalled games. Local manifests yield Steam `GameId`, name, install directory, installed state, and Windows platform. When account import is enabled, `PlayerService.ToGame` yields AppID as `GameId`, localized name, Steam source, Windows platform, playtime, and last activity. The aggregator can merge install size, Family Sharing source, additional accounts, explicit AppIDs, and locally installed state according to settings. [defaults](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/SteamLibrarySettingsViewModel.cs#L33-L51), [`SteamLocalService.GetInstalledGameFromFile`](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/SteamLocalService.cs#L72-L127), [`PlayerService.PlayerServiceGetOwnedGames` and `ToGame`](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/PlayerService.cs#L36-L72), [`SteamServiceAggregator.GetGamesAsync`](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/SteamServiceAggregator.cs#L39-L76)
3. **Metadata is requested per game and selected per field.** `MetadataDownloader.DownloadMetadataAsync` processes games sequentially. For each configured field, `ProcessField` walks that field's ordered source list and stops at the first source that returns valid data. It caches one complete `GameMetadata` result from the game's library provider and one on-demand provider instance per metadata plugin for the duration of that game, so selecting the Steam source for several fields does not invoke `SteamMetadataProvider.GetMetadata` repeatedly. [official configuration rule](https://codeberg.org/Playnite/Docs/src/commit/aa07876a6646fe163cd9df5434918a893fa8119c/docs/manual/features/extensionsSupport/installingExtensions.md#L43-L49), [`MetadataDownloader.ProcessField`](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/Metadata/MetadataDownloader.cs#L136-L215), [`DownloadMetadataAsync`](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/Metadata/MetadataDownloader.cs#L311-L365)
4. **Steam's own metadata provider uses provider identity, not title search.** `SteamMetadataProvider.GetMetadata` parses `game.GameId` as a Steam `GameID` and calls `MetadataProvider.GetGameMetadata` with its AppID. That method obtains Steam product info, Store details, reviews, and media by AppID. [Steam ID conversion](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/GameExtension.cs#L6-L16), [`SteamMetadataProvider.GetMetadata`](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/SteamMetadataProvider.cs#L49-L62), [`MetadataProvider.GetGameMetadata`](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/SteamShared/MetadataProvider.cs#L291-L313)
5. **The default IGDB path is ID-first with a title fallback.** In background mode, `IgdbLazyMetadataProvider.GetIgdbMetadata` sends name, release year, library plugin ID, and source `GameId` to Playnite's backend. `GamesController.GetMetadata` first maps the Steam plugin ID and AppID to an IGDB external-game record; only when that fails does `TryMatchGame` perform sanitized title matching, with release-year disambiguation. Manual IGDB download instead opens a title-initialized chooser and allows an IGDB numeric ID. Therefore Playnite as a whole is not exclusively title-based, but only the same-library Steam metadata path is guaranteed to be directly AppID-addressed. [IGDB request construction](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Metadata/IGDBMetadata/IgdbLazyMetadataProvider.cs#L405-L461), [`GamesController.GetMetadata`](https://codeberg.org/Playnite/Backend/src/commit/12a6864210e749558dbdc5737e0c6e15f582a0df/source/PlayniteServices/Controllers/IGDB/GamesController.cs#L95-L139), [`TryMatchGame`](https://codeberg.org/Playnite/Backend/src/commit/12a6864210e749558dbdc5737e0c6e15f582a0df/source/PlayniteServices/Controllers/IGDB/GamesController.cs#L601-L677)
6. **Automatic download is a core setting applied after an import trigger.** `PlayniteSettings.DownloadMetadataOnImport` defaults to `true`. A manual library update or a configured startup library update calls `UpdateLibrary`; after discovery and persistence, `UpdateLibraryData` downloads metadata for `addedGames` only. Library-update frequency defaults to every startup and supports manual, every startup, daily, or weekly. On first application start, Playnite imports without inline enrichment and then runs the general metadata download. The official manual also exposes bulk and single-game metadata downloads. [`DownloadMetadataOnImport`](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/Settings/PlayniteSettings.cs#L873-L886), [startup frequency](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/Settings/PlayniteSettings.cs#L2125-L2134), [`ProcessStartupLibUpdate` and `UpdateLibrary`](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/ViewModels/MainViewModelBase.cs#L512-L601), [first start](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite.DesktopApp/DesktopApplication.cs#L222-L233), [official metadata manual](https://codeberg.org/Playnite/Docs/src/commit/aa07876a6646fe163cd9df5434918a893fa8119c/docs/manual/library/games/metadata.md#L30-L51)
7. **Fields and provider order are independently configurable.** The current default enables IGDB for most fields, prefers Steam's library provider before IGDB for description, icon, and background, prefers IGDB before Steam for cover, and disables name replacement. `Guid.Empty` represents the importing library's official metadata provider inside `MetadataDownloader.ProcessField`. [`MetadataDownloaderSettings.GetDefaultSettings`](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/Metadata/MetadataDownloaderSettings.cs#L306-L339), [library-source dispatch](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/Metadata/MetadataDownloader.cs#L178-L215)

## Failure and rate-limit behavior

- Steam owned-games and last-played requests use `SteamApiRetrySettings(5, 5, 429)`: up to five retries after the initial request, a fixed five-second delay, and retries only for HTTP 429. The code does not inspect `Retry-After`. [`PlayerService`](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/PlayerService.cs#L24-L52), [`SteamApiServiceBase.Get`](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/Base/SteamApiServiceBase.cs#L16-L56)
- Steam Store metadata requests use `MetadataProvider.SendDelayedStoreRequest`: at most ten attempts with a fixed 2.5-second sleep when a `WebException` message contains `429`; exhaustion returns no value. Product-info retrieval has no explicit retry in this class and returns no value after a caught failure. [`SendDelayedStoreRequest`](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/SteamShared/MetadataProvider.cs#L64-L107), [`DownloadGameMetadata`](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/SteamShared/MetadataProvider.cs#L142-L167)
- Playnite core catches source failures, tries the next configured source for that field, and continues with later fields and games. Its metadata loop is sequential and has cancellation, but no central rate limiter, exponential backoff, or automatic second pass. [`ProcessField`](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/Metadata/MetadataDownloader.cs#L293-L308), [`DownloadMetadataAsync`](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/Metadata/MetadataDownloader.cs#L320-L358)

These are implementation observations, not a published Steam service guarantee. In particular, the fixed delays and message-based Store 429 detection should not be copied as a protocol contract.

## GameVault recommendation

GameVault should mirror the architectural behavior, not Playnite's general extension framework:

- Persist the Steam AppID and basic imported title/ownership result before enrichment. Treat `(provider, provider game ID)` as the exact identity and use title matching only for cross-provider canonical reconciliation, with confirmation when ambiguous.
- Keep ownership refresh and catalog enrichment independently retryable. A failed metadata request must not invalidate a successful ownership snapshot or remove an existing usable card.
- Request Steam metadata directly by AppID. Pass provider identity, title, and release year to a fallback provider when available, but do not assume a fallback can map every Steam AppID exactly.
- Enrich each newly created game after the user-triggered account refresh and resume incomplete metadata at startup. This startup pass must not call the owned-library API or change ownership.
- Process enrichment sequentially. Persist successful per-game completion, honor `Retry-After`, and retain failures for a later pass. When Steam omits the header, use Playnite's bounded ten-attempt, 2.5-second fallback without copying its message-string inspection.
- Preserve personal fields and existing metadata unless the user explicitly requests replacement. GameVault needs a small source-priority policy, not Playnite's plugin runtime or a configurable provider chain for every field.

Do not copy SteamKit product-info loading, Store review/tag scraping, Family Sharing aggregation, client manifest scanning, Playnite's backend AppID-to-IGDB mapping, or installable plugin APIs unless a concrete GameVault requirement needs them. The useful seam is `library identity -> persisted game -> independent metadata enrichment`, with provider IDs retained end to end.
