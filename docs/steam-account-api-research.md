# Steam Account API Research

Research for issues [#4](https://github.com/SergioGL-14/GameVault/issues/4) and [#35](https://github.com/SergioGL-14/GameVault/issues/35), checked against Valve-owned documentation on 2026-09-06.

## Recommendation

Prioritize Playnite-style **Web login** for a usable own-account connection and retain the user's Steam Web API key as an advanced fallback. The web route trades a smaller setup burden and better private-library access for dependence on undocumented Steam Store session details. Keep that risk inside one replaceable main-process adapter, isolate and clear its browser storage, never expose its bearer token to the renderer, and preserve the documented personal-key route when Steam changes the web flow.

Do not ship a GameVault-owned key. Valve requires keys to remain confidential and makes the key owner responsible for their use. A shared key embedded in Electron cannot satisfy that requirement. Publisher keys are expressly server-only. Steam OAuth is also not a general alternative: Valve assigns client IDs after direct contact and says it will not provide one unless the integration supports its specified Cloud or Workshop cases. [Authentication](https://partner.steamgames.com/doc/webapi_overview/auth), [OAuth](https://partner.steamgames.com/doc/webapi_overview/oauth), [API terms, sections 1-2](https://steamcommunity.com/dev/apiterms)

## Comparison with Playnite SteamLibrary 2.44

Playnite does not secretly supply a Web API key. Its default **Web login** opens `https://store.steampowered.com/explore/` in Playnite's embedded Chromium view, lets Steam run the official sign-in flow, and then reads the signed-in page's `data-userinfo` and `data-store_user_config` attributes to obtain the SteamID and `webapi_token`. On each later import it revisits that page in an off-screen view and derives a fresh in-memory token from the retained Steam web session. The plugin stores the SteamID in settings but does not serialize this access token. Playnite configures one persistent browser cache with `PersistSessionCookies = true`, so Steam cookies, including session cookies, persist under Playnite's `browsercache`; its manual says clearing web cache resolves authentication failures. [SteamStoreService.cs](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/SteamStoreService.cs#L16-L28), [token extraction and login](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/SteamStoreService.cs#L48-L77), [session reuse](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/SteamStoreService.cs#L100-L157), [CEF persistence](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/CefTools.cs#L20-L48), [browser-cache location](https://github.com/JosefNemec/Playnite/blob/98c09dd6a16369feaa34c9661bc20b47566d76b1/source/Playnite/Settings/PlaynitePaths.cs#L90-L100), [Playnite troubleshooting](https://api.playnite.link/docs/manual/gettingStarted/helpAndTroubleshooting/troubleshooting.html#authentication-and-syncing-issues)

The Steam extension never asks Playnite code for a Steam password and contains no password field for Web login: credentials and Steam Guard are entered into Steam's own page inside the embedded browser. Playnite's published security description says integrations generally retain web-session cookies or tokens rather than credentials, and Valve prohibits an API client from intercepting or storing a Steam password. The browser session and extracted bearer token are nevertheless credentials: compromise of Playnite's shared browser profile or process can expose authenticated Steam access until Valve expires or revokes the session. [Playnite FAQ](https://api.playnite.link/docs/manual/gettingStarted/helpAndTroubleshooting/faq.html#is-playnite-safe-to-use), [Steam API terms, section 2](https://steamcommunity.com/dev/apiterms)

For the Web-login import, the plugin sends the extracted token as the `access_token` query parameter to `IPlayerService/GetOwnedGames/v1`, `IPlayerService/ClientGetLastPlayedTimes/v1`, `IClientCommService/GetClientAppList/v1`, `IFamilyGroupsService/GetFamilyGroupForUser/v1`, `IFamilyGroupsService/GetSharedLibraryApps/v1`, and `IParentalService/GetParentalSettings/v1`. If the client-app list yields no games, it reads `https://store.steampowered.com/dynamicstore/userdata/` and asks Playnite's own backend for names of newly found AppIDs. `GetOwnedGames` is the core owned-library call; the other calls add playtime, client-only/free items, Family Sharing, and parental filtering. [PlayerService.cs](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/PlayerService.cs#L12-L52), [ClientCommService.cs](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/ClientCommService.cs#L16-L27), [FamilyGroupsService.cs](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/FamilyGroupsService.cs#L12-L48), [ParentalService.cs](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/ParentalService.cs#L9-L22), [aggregation and fallback](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/SteamServiceAggregator.cs#L144-L193), [fallback metadata](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/Services/SteamServiceAggregator.cs#L259-L292)

Playnite's authenticated Web route is its richer own-account route and does not rely on the profile being public. Public visibility does not provide keyless account import: the alternative **API key login** requires a SteamID and that account's user key, and additional accounts each require their associated key. The plugin internally selects that route with `IsPrivateAccount`, validates that a key is present, and stores API keys separately in an encrypted `keys.dat` bound to the Windows user SID. The official plugin guide recommends Web login for the fuller library and API-key login only when the user prefers not to sign in through Playnite's browser. [settings and key persistence](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/SteamLibrarySettingsViewModel.cs#L25-L67), [route selection](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/SteamServiceAggregator.cs#L147-L177), [key validation and storage](https://github.com/JosefNemec/PlayniteExtensions/blob/3085ebd8b5906b53d3f005ef08141d641f4c469d/source/Libraries/SteamLibrary/SteamLibrarySettingsViewModel.cs#L160-L213), [Steam troubleshooting](https://github.com/JosefNemec/PlayniteExtensions/wiki/Steam-troubleshooting#should-i-use-web-or-api-login)

GameVault accepts the Web-login maintenance cost because connection usability and private own-library access are primary product requirements. The implementation uses Store login, SteamID and temporary-token extraction, and the authoritative `GetOwnedGames` snapshot. It deliberately omits `GetClientAppList` because client visibility is not proof of ownership. The web token is not used with `GetPlayerSummaries` or achievement APIs because Playnite does not establish those contracts; the web route retains a neutral local account label rather than storing Steam's private account login name. It does not add Family Sharing, parental-control, playtime, or backend metadata calls. The adapter must fail closed if Steam changes page markup and direct the user to reconnect or use the documented key fallback. [GetOwnedGames](https://partner.steamgames.com/doc/webapi/IPlayerService#GetOwnedGames), [Web API authentication](https://partner.steamgames.com/doc/webapi_overview/auth), [Playnite's Web/API guidance](https://github.com/JosefNemec/PlayniteExtensions/wiki/Steam-troubleshooting#should-i-use-web-or-api-login)

## Credential and transport contract

- A user key is available to any Steam account holder who supplies an associated domain, accepts the API terms, and registers at [Steam's key page](https://steamcommunity.com/dev/apikey). The domain field is a registration association, not a request-origin restriction documented by Valve. [Authentication](https://partner.steamgames.com/doc/webapi_overview/auth)
- Send requests over HTTPS to the public host. Valve documents `api.steampowered.com` for public Web API clients. `partner.steam-api.com` requires a publisher key and is for secure publisher servers. [Web API overview](https://partner.steamgames.com/doc/webapi_overview)
- Send the key in the `x-webapi-key` header rather than a query string. Both forms are supported; the header reduces accidental exposure in URLs, browser history, proxies, and logs. Never log the header. [Authentication](https://partner.steamgames.com/doc/webapi_overview/auth)
- Store a user-entered key only through Electron `safeStorage`, outside SQLite and renderer state. Refuse persistence when secure encryption is unavailable and provide removal/replacement. The first Steam delivery deliberately does not support an environment override, ensuring connection and refresh use the same validated key. This is GameVault's security design, not a storage mechanism prescribed by Valve.
- Keep Web-login cookies in a dedicated persistent Electron partition, retain extracted bearer tokens only in main-process memory, restrict top-level navigation to Steam-owned HTTPS hosts, deny browser permissions and popups, and clear all session storage on disconnect. This limits exposure but does not turn Steam's undocumented Web-login route into a stable or officially supported contract.
- Valve's terms require the key to remain confidential; prohibit sharing it; make its owner responsible for its use; prohibit intercepting or storing Steam passwords; and permit Valve to change, suspend, or terminate the API. GameVault must never request Steam credentials. [API terms, sections 1, 2, 10-11](https://steamcommunity.com/dev/apiterms)
- The terms also require a privacy policy for nonpublic user data, retrieval only at the user's request, and disclosure of what is stored and in which countries. A local-only implementation should state that the key and imported Steam data remain on the user's device. [API terms, section 2](https://steamcommunity.com/dev/apiterms)

## Steam identity

Steam's Web API identifies a user with a 64-bit Steam ID (`uint64`). JSON encodes 64-bit numbers as strings, so GameVault must preserve SteamID64 as a decimal string and never convert it to a JavaScript `number`. [Web API overview](https://partner.steamgames.com/doc/webapi_overview), [response formats](https://partner.steamgames.com/doc/webapi_overview/responses)

Accept only these user inputs:

- A decimal SteamID64, retained as a string after syntax and unsigned-64-bit range validation.
- `https://steamcommunity.com/profiles/<steamid64>/`, parsed as the same numeric input.
- `https://steamcommunity.com/id/<vanity>/`, parsed and resolved with `ISteamUser/ResolveVanityURL/v1`, using required `key` and `vanityurl`; omit `url_type` because its default is individual profile (`1`). [ResolveVanityURL](https://partner.steamgames.com/doc/webapi/ISteamUser#ResolveVanityURL)

Numeric shape or range checks do not prove that an individual account exists. Validate the normalized ID by requesting one player from `ISteamUser/GetPlayerSummaries/v2` and require exactly one returned entry whose `steamid` equals the requested value. Reject an unresolved vanity name, an empty player list, or a mismatched ID. Valve's current reference does not document `ResolveVanityURL`'s response fields or failure payload, so do not depend on community-documented numeric `success` codes. [ISteamUser](https://partner.steamgames.com/doc/webapi/ISteamUser)

Steam also documents OpenID as a way for a website to authenticate a SteamID without receiving a password. It identifies the user but does not grant the user-key access required by the library and achievement methods, so it does not remove the personal-key requirement for this desktop flow. [Steam Web API documentation](https://steamcommunity.com/dev)

## `GetPlayerSummaries`

Stable documented request: `GET /ISteamUser/GetPlayerSummaries/v2/` with user `key` and comma-separated `steamids`, maximum 100. GameVault needs one ID. The documented example returns `response.players[]` with `steamid`, `communityvisibilitystate`, `profilestate`, `personaname`, `profileurl`, avatar URLs, and potentially activity/profile fields. Valve cautions that this method is for displaying user information on a website and points game clients to client APIs; GameVault is not a Steamworks game client, so it has no applicable Steam client API identity context. [GetPlayerSummaries](https://partner.steamgames.com/doc/webapi/ISteamUser#GetPlayerSummaries)

For #4, retain only `steamid`, `personaname`, and one avatar URL if the UI displays them. Do not retain presence, last-logoff, real-name, location, game activity, or other optional profile fields. Valve says persona name and avatar are API-accessible at minimum, while additional profile information follows the user's privacy controls. [Steam privacy policy, sections 3.1 and 5.4](https://store.steampowered.com/privacy_agreement/)

## `GetOwnedGames`

Stable documented request: `GET /IPlayerService/GetOwnedGames/v1/` with user `key`, `steamid`, `include_appinfo`, `include_played_free_games`, and optional `appids_filter`. It returns the player's games only when owned games/game details are visible to the caller. `include_appinfo=true` requests each game's name and icon. Free games are excluded by default; `include_played_free_games=true` includes free games the user has played. [GetOwnedGames](https://partner.steamgames.com/doc/webapi/IPlayerService#GetOwnedGames)

Use `include_appinfo=true`, `include_played_free_games=true`, and no `appids_filter` for a complete refresh. This yields the only documented single-call full snapshot, including played free titles that Valve otherwise omits. Treat those entries as Steam-reported library entries rather than proof of a permanent paid license.

Valve's current reference guarantees a list and the optional name/icon details but does not publish a normative JSON response schema. Common fields such as `response.game_count`, `response.games`, `appid`, `name`, `img_icon_url`, playtime values, last-played time, and community-stats indicators must therefore be parsed defensively. For #4, require an array of entries with unique valid `appid` values. Preserve an entry whose optional app-info name is absent with an explicit `Steam App <appid>` title instead of silently omitting it or rejecting the complete snapshot. Do not require the undocumented `game_count` to equal the array length, but reject an empty array when a positive integer count proves it is incomplete. Ignore and do not store icons, playtime, recent activity, platform playtime, and community-stat fields because #4 excludes them.

The method documents no cursor, page number, result limit, or pagination procedure. One successful response is the complete visible result set. Do not invent pagination or call undocumented library endpoints. An absent/invalid games collection is not a valid empty snapshot and must not deactivate prior ownerships. A structurally valid empty collection may represent no visible games, but because Valve does not document the privacy response shape, GameVault should present it for confirmation or classify it as privacy-limited rather than silently replacing a prior non-empty snapshot.

Steam's privacy policy says additional account information is controlled from the Community profile and public profile data can be accessed through the API. `GetOwnedGames` states the narrower operational rule: results exist only when games/game details are visible to the caller. GameVault cannot bypass that choice merely because the user supplied their own key. [Steam privacy policy, section 5.4](https://store.steampowered.com/privacy_agreement/), [GetOwnedGames](https://partner.steamgames.com/doc/webapi/IPlayerService#GetOwnedGames)

## Achievements for #35

SuccessStory does not pass Playnite's Store token to `ISteamUserStats`. It obtains definitions from the currently undocumented `IPlayerService/GetGameAchievements/v1` method through SteamKit, then reads the connected player's Community achievement page with retained Steam cookies. The definition response includes a stable internal name plus localized text and both colored and gray icon filenames. The Community page exposes achievement rows, the displayed icon variant, and unlock text, allowing those rows to be mapped back to definitions. This route works with Web login but depends on two undocumented contracts and must remain isolated from library refresh. [SuccessStory Steam adapter](https://github.com/Lacro59/playnite-successstory-plugin/blob/36a09ba06e1e4875d6f7fc1ce5c832f37681d87f/source/Clients/SteamAchievements.cs), [shared Steam adapter](https://github.com/Lacro59/playnite-plugincommon/blob/7718625d8ef6eacd2671ec08a6d9fa779c39e327/CommonPluginsStores/Steam/SteamApi.cs), [SteamKit wrapper](https://github.com/Lacro59/playnite-plugincommon/blob/7718625d8ef6eacd2671ec08a6d9fa779c39e327/CommonPluginsStores/Steam/SteamKit.cs)

The smallest Web-login implementation for GameVault is therefore a separate explicit achievement operation: request definitions without credentials, load the connected account's Community page through the existing isolated Electron session, map icon variants to stable internal names, and replace evidence only after a complete match. It needs no SteamKit dependency or generic plugin runtime. The personal API-key route can continue using the documented methods below.

`ISteamUserStats/GetSchemaForGame/v2` requires a user `key` and `appid`; optional `l` selects localization. It returns the game's complete stats and achievement schema. GameVault needs achievement definitions only and should ignore stats. Definition data should be normalized around the provider achievement name/key, localized display name and description, hidden flag, and available icon references. [GetSchemaForGame](https://partner.steamgames.com/doc/webapi/ISteamUserStats#GetSchemaForGame)

`ISteamUserStats/GetPlayerAchievements/v1` requires a user `key`, `steamid`, and `appid`; optional `l` selects localization. It returns achievements the specified user has unlocked/state for that app. GameVault needs only the provider achievement name/key, achieved state, and unlock timestamp where supplied; schema owns display metadata. [GetPlayerAchievements](https://partner.steamgames.com/doc/webapi/ISteamUserStats#GetPlayerAchievements)

Valve does not document method-specific HTTP statuses or payloads for a private profile, an app with no achievements, an invalid app, or a user who has no stats. The only stable failure contract is the generic Web API guidance: `400` bad parameters, `401`/`403` access denied, `429` rate limited, `500` internal failure, and `503` unavailable. It also warns that fields can arrive in arbitrary order. [Error codes and responses](https://partner.steamgames.com/doc/webapi_overview/responses)

Consequently, #35 treats each game as a complete snapshot only when its definition and player-state responses are successful and structurally valid. A valid definition response with no achievements means the title has no known Steam achievements and does not require a player-state call. Any non-2xx response, explicit unsuccessful payload, malformed entry, duplicate identity, or mismatch between player rows and definitions is an incomplete per-game refresh; preserve that game's previous snapshot. Do not encode observed error strings or status behavior as a stable Valve contract.

Steam exposes achievement definitions and per-achievement unlock state, not a documented universal game-completed flag. GameVault may derive achievement completion only when at least one known achievement exists and every effective achievement is complete. Titles without known achievements retain manual game status. [ISteamUserStats](https://partner.steamgames.com/doc/webapi/ISteamUserStats)

## Limits and stability

- Valve's terms impose a documented limit of **100,000 Web API calls per day**. [API terms, section 2](https://steamcommunity.com/dev/apiterms)
- Valve documents HTTP `429` for rate limiting but publishes no per-second quota, burst allowance, response headers, or retry interval for these methods. Metadata enrichment retries one Store AppID up to ten times, honoring `Retry-After` when present and using Playnite's 2.5-second fallback when Steam omits it. Exhaustion stops fan-out and leaves the remaining work pending. [Error codes and responses](https://partner.steamgames.com/doc/webapi_overview/responses)
- `GetPlayerSummaries/v2`, `ResolveVanityURL/v1`, `GetOwnedGames/v1`, `GetSchemaForGame/v2`, and `GetPlayerAchievements/v1` are listed in the official Steamworks Web API reference and are the stable documented surface, subject to Valve's right to change or terminate it.
- Steam Store `/api/storesearch`, `/api/appdetails`, Community profile XML, scraping profile/library pages, and similarly discoverable endpoints are not in the official Steamworks Web API reference. They are undocumented contracts and must not be required for account refresh correctness. Existing Store endpoints may remain optional catalog enrichment under their separately documented risk.

## Minimal manual-refresh data

Issue #4 needs exactly this provider access:

1. On default connection, authenticate in Steam's Store page and extract one signed-in SteamID and temporary token. Retain the SteamID with a neutral local account label; do not store the Store page's private account login name. On advanced key connection, resolve a vanity segment only when supplied, call `GetPlayerSummaries/v2`, and keep the SteamID, displayed persona name, and one displayed avatar URL.
2. On explicit **Refresh now**, call `GetOwnedGames/v1` once with that SteamID64, `include_appinfo=true`, and `include_played_free_games=true`. Keep `appid` as provider identity and the name needed for matching and title-only fallback cards. Ignore icons, playtime, and all social or activity data.
3. Commit the owned-game snapshot before calling the existing Store `appdetails` catalog adapter once per pending AppID. A successful merge marks that provider entry complete; failed and unvisited entries remain pending for a later automatic pass without invalidating ownership. Do not call `GetClientAppList`, achievement, friends, recently played, review, or presence APIs as part of #4.

Issue #35 later adds one separate achievement refresh. The API-key route uses localized `GetSchemaForGame/v2` and `GetPlayerAchievements/v1`. The Web-login route uses `IPlayerService/GetGameAchievements/v1` definitions and the authenticated Community page instead of incorrectly sending the Store token to `ISteamUserStats`. Cache definitions by AppID/language and replace player evidence only from a complete per-game pair. Execute sequentially or with low bounded concurrency and stop cleanly on `429`.
